# Infrastructure / Cloud 포트폴리오 로드맵

- 기준일: 2026-11-01
- 목표: 2027년 4월 일본에서 Infrastructure / Cloud Engineer 주니어 직무로 입사한다. 기존 쇼핑몰을 workload로 사용해 Linux, network, AWS, 운영·자동화 역량을 증명한다.
- 학습 리듬: 평일에는 30~45분 단위로 흐름을 유지하고, 주말 작업 시간을 점진적으로 늘린다. 매일 작업하는 것을 조건으로 삼지 않되, 주간 결과물과 지원 활동을 남긴다.
- 자격증: SAA는 비용 부담을 고려해 보류한다. 우선 hands-on과 설명 가능한 결과물을 만든 뒤, 예산이나 회사 지원이 생길 때 다시 판단한다.

## 목표와 프로젝트 방향

첫 목표는 곧바로 DevOps/SRE가 아니라 Linux, network, server, cloud 운영과 구축을 경험할 수 있는 주니어 Infrastructure / Cloud 직무다. 현재 비IT 경력을 IT 실무경력처럼 표현하지 않고, 검사·이상 확인·원인 추적·결과 기록 경험은 전이 가능한 역량으로 설명한다.

쇼핑몰을 처음부터 다시 만들거나 결제 기능을 모두 복구하는 것이 목적은 아니다. 기존 앱을 최소한으로 실행 가능한 상태로 두고, 클라우드 배포와 보안·비용 판단, 재현성, 모니터링, 장애 분석을 단계적으로 보여준다.

## 진행 스냅샷 — 2026-11-01

### 현재 완료 상태

- 로컬 MariaDB 기반으로 회원가입·메일 인증·로그인·관리자 상품 등록/수정·상품 상세와 페이지네이션을 확인했다.
- Maven Wrapper와 Java 21 환경을 복구했고, JAR 실행, 8080 포트 확인, 로그 확인, 정상 종료를 검증했다.
- `application-ec2.properties`를 추가해 DB, 메일, OAuth, 업로드 경로를 환경변수로 분리했다. 실제 비밀값은 저장소에 넣지 않는다.
- Actuator health endpoint를 추가하고 `/actuator/health`가 EC2 profile에서 HTTP 200과 `UP`을 반환하는 것을 확인했다. 상세 상태는 외부에 노출하지 않는다.
- AWS Free Plan 계정, IAM 사용자 MFA, AWS CLI profile을 준비했다. 아직 EC2, RDS, S3 등 과금 가능 리소스는 생성하지 않았다.

### 11월 — 첫 수동 배포와 운영 근거

- **1주차:** Free Plan과 비용·삭제 기준을 다시 확인한 뒤 EC2 한 대에만 배포한다. 처음에는 비용과 복잡도를 낮추기 위해 애플리케이션과 MariaDB를 같은 인스턴스에 둔다.
- **2주차:** SSH 공개보다 Session Manager를 우선 사용하고, Nginx → Spring Boot 8080 → health endpoint 흐름을 구성한다. JAR를 systemd service로 등록한다.
- **3주차:** service 재시작, 포트/권한/디스크 또는 DB 연결 문제 중 한 가지를 의도적으로 재현하고, 로그로 원인을 확인해 복구한다.
- **4주차:** 아키텍처 그림, Security Group·IAM·비용·삭제 절차를 정리한다. 일본어 이력서와 職務経歴書의 초안을 만든다.

완료 기준: 단일 EC2 배포의 선택 이유, 접속 방식, 로그 확인, health check, 종료·삭제 절차와 한계(단일 서버·단일 DB)를 설명할 수 있다.

- 첫 페이지에 상품 12개, `/?page=1`에 나머지 상품 1개가 표시되는 것을 확인했다. 두 번째 페이지에서 이전은 활성화되고 다음은 비활성화된 상태로 보였다.
- 테스트 상품은 로컬 DB에만 있으며 코드 변경은 없다. 관리자 상품 등록을 위해 테스트 계정 역할을 로컬에서 `ADMIN`으로 올린 상태다.
